# Flight Radar Oracle

An experimental, self-hosted flight-deal monitor built in Python + SQLite, designed for Oracle Cloud Always Free Ampere A1.

> **État réel (14 octobre 2026) :** site Vercel déployé et vérifié publiquement ; API et stockage d'illustrations installés sur la VM Oracle existante (Nuvio conservé). La collecte non officielle a fonctionné sur GitHub Actions, mais a échoué depuis Oracle. **Le miroir GitHub → Oracle est préparé, non activé à distance.** Aucun tarif n'est garanti réservable.

## Capabilities

- Route planning for Belgian, French, Dutch and nearby airports
- SQLite history: comparisons on the same origin/destination, departure/return dates, airline, cabin, stops and declared baggage
- Daily price median baseline, minimum historical evidence (8 distinct days)
- Deal scoring, minimum discount and deduplication
- Manual revalidation of deals before public notification
- Experimental `fast-flights` adapter (unofficial, disabled unless expressly opted in)
- JSON import, local-only dashboard, Telegram alerts
- OCI ARM64 installation, systemd restart, SQLite daily backups, GitHub CI and manual SSH deployment

## Vercel — public web experience (recommended deployment)

The `public/` site and `api/*.mjs` are now Vercel-ready. `vercel.json` uses Framework **Other**, Output Directory **public**. Import **this repository** as a new Vercel project; keep existing Nuvio projects separate.

**Important:** the public `/api/deals` currently reads indicative observed fares produced by a bounded, experimental GitHub Actions collection. Offers are **not booking-verified**; they disappear from the API when stale. There is no payments or subscriber alerts system. You may later connect another authorized HTTPS feed via `FLIGHT_RADAR_FEED_URL` and optional server-side token. See `data/market.json` for the last actual collection status.

See **[Vercel deployment and limitations](VERCEL.md)**. Vercel Hobby is personal/non-commercial only; the intended paid-subscription business would need suitable commercial hosting terms.

## Quick start

Requires Python 3.10+ (Python 3.12 recommended). No paid API is necessary for the synthetic demo or JSON imports.

```bash
python -m flight_radar init
python -m flight_radar demo
python -m flight_radar report
python -m flight_radar serve
```

Dashboard: http://127.0.0.1:8080 (binds to loopback; no authentication). Data generated by `demo` is explicitly synthetic.

Run tests:

```bash
python -m unittest discover -s tests -v
```

Import real observations collected from a permitted source:

```bash
python -m flight_radar scan --source json --file fares.json
```

Each JSON element must have `origin`, `destination`, `departure_date`, `return_date`, `price_eur`, `carrier`, `source`; optional `stops`, `cabin`, `baggage`, `link`, `details`, `collected_at`. Dates are ISO `YYYY-MM-DD`. No API key is required for JSON imports.

Experimental Google Flights adapter (only when you have verified applicable access terms):

```bash
python -m pip install -r requirements-optional.txt
python -m flight_radar scan --source fast-flights --allow-unofficial-collection --limit 2
```

It is not guaranteed to work or be allowed for all workloads. It does not bypass anti-bot challenges. The experimental collector runs on GitHub Actions **three times daily**, currently limited to three searches per cycle; success depends on provider access. The Oracle VM's direct provider queries have returned unparsable content, so do **not** enable aggressive scans there.

## Oracle Cloud

**Existing shared VM beta:** the isolated local gateway, timers and 18 self-generated destination SVG illustrations are installed on Oracle, with Nuvio still active. Activate the safer GitHub-to-Oracle snapshot mirror per [Oracle shared VM runbook](deploy/oci/SHARED_VM_RUNBOOK.md) after validating the host. The original installer below describes an **alternative standalone dashboard install**, not the already deployed shared-VM setup.

See [Oracle deployment instructions](deploy/oci/README.md). On a new Ubuntu ARM VM:

```bash
git clone https://github.com/aziriel2020/flight-radar-oracle.git
cd flight-radar-oracle
sudo bash deploy/oci/install.sh
curl http://127.0.0.1:18080/health
```

The installer keeps the dashboard private on the VM at 127.0.0.1:18080; access it using an SSH tunnel. Never expose it directly as a public commercial site without adding HTTPS, authentication and rate limiting. Systemd runs it on reboot; a timer stores consistent SQLite backups locally for 14 days. Off-machine backups are not configured.

GitHub Actions `Deploy to Oracle Cloud (manual)` requires an **existing** VM and four repository secrets: `OCI_HOST`, `OCI_USER`, `OCI_SSH_KEY`, `OCI_SSH_KNOWN_HOSTS`. It does not provision OCI resources or generate credentials.

This is a technical MVP, not a bookable flight aggregator. Price completeness, legal access, false positives, capacity, customer support, GDPR compliance, public auth, billing and production monitoring remain unverified or incomplete.

See [Product plan](PLAN_PRODUIT.md) for expansion ideas.
